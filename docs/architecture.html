How It Works

An overview of the reconstruction pipeline, the options you can configure, and how the synthetic and clinical data paths feed the same training code.

The Reconstruction Pipeline

The method takes sparse 2D X-ray projections and produces a 3D vessel mesh. The key idea is to use a preoperative CTA scan as a structural prior that anchors the reconstruction, turning the problem from unconstrained 3D inference into guided shape completion.

At a high level, the pipeline is:

  1. CTA Prior Extraction — a vessel segmentation from CTA is converted into a 3D point cloud.
  2. Gaussian Initialization — 3D Gaussians are seeded from the prior points and optional context points.
  3. Optimization — the Gaussians are optimized to match the input DSA projections.
  4. Mesh Extraction — the final opacity field is queried on a voxel grid and converted to a vessel mesh via marching cubes.

Initialization Options

The initial Gaussian set is built from two populations:

  • M1 — Anatomical prior (always used): points sampled from the CTA vessel segmentation. This is the backbone of the reconstruction. Controlled by --ply_path and the M1 point budget.
  • M2 — Context points (optional, recommended): additional points that help reconstruct vessels not covered by the CTA prior. Available modes are residual, uniform, and FDK-based initialization.

Loss Functions

Training uses a combination of losses, each configurable through the CLI and optional YAML config:

Loss Purpose Typical Weight
L1 Pixel-level reconstruction accuracy 0.93
DSSIM Structural similarity 0.07
Prior Anchoring Keeps Gaussians close to the CTA geometry 0.0025
FN Loss Penalizes missing vessels in the rendered projections configurable

Evaluation Metrics

Two types of metrics are computed:

  • 2D Rendering Quality — PSNR and SSIM on re-rendered projections.
  • 3D Mesh Accuracy — Chamfer Distance and Hausdorff Distance in mm against the reference anatomy.

When a CTA prior is available, the 3D metrics are partitioned into:

  • Missing region — vessels not covered by the prior
  • Prior region — vessels already present in the CTA prior

Configuration

Training settings can be controlled directly from the CLI or through your own YAML config passed to train.py --config. Settings are layered in this order:

  1. Built-in defaults
  2. Your --config YAML file
  3. Command-line flags

Common controls include:

  • Loss weights — balance between L1, DSSIM, prior anchoring, and FN loss
  • Iteration count — total optimization steps
  • Point budgets — M1 and M2 initialization sizes
  • Densification schedule — when to stop adding or splitting Gaussians
  • Opacity field type — the neural field architecture used for opacity prediction

Clinical Data Pipeline

In addition to the synthetic TopBrain pipeline, the repository supports real clinical DSA data through the data_generation.clinical module. The clinical pipeline converts registered DSA acquisitions into the same training format used by the synthetic data path.

  1. DICOM to DSA MIP — load angiography stacks, subtract mask and fill phases, and form MIPs.
  2. CTA Prior Extraction — extract vessel voxels from CTA segmentation and convert them to world coordinates.
  3. Visual Hull Filtering — remove prior points inconsistent with the 2D DSA evidence.
  4. Dataset Export — write transforms.json, projections, priors, and optional residual point clouds.

The exported clinical dataset uses the same training interface as the synthetic pipeline. See Clinical Data for the full guide.

Prior Thickness Settings

The CTA prior can be filtered by vessel diameter. Thinner thresholds retain more anatomy, while thicker thresholds provide a cleaner but less complete prior.

Setting Threshold Typical Coverage
All vessels none highest
> 1.0 mm 1.0 mm high
> 1.5 mm 1.5 mm medium
