Guide

Clinical Data

Generate clinical training datasets from registered DSA acquisitions and CTA-derived vessel priors. The repository supports this pipeline directly; patient data and registration outputs must be supplied by the user.

1 Prerequisites

Use the same repo environment as the synthetic TopBrain pipeline: 

uv python install 3.10
./scripts/uv.sh sync --verify

The default environment already includes the required clinical readers such as pydicom and SimpleITK.

Upstream Registration

Before running this pipeline, each DSA acquisition must be registered to the CTA volume. In the original study, this step was performed with X-ray/volume registration tooling outside this repository. The export expects a parameters.pt file per view containing the final camera pose and projection geometry.

What parameters.pt Must Contain

The registration checkpoint is expected to contain the following information:

  • final_pose — 4×4 camera-to-world matrix
  • drr.sdd — source-to-detector distance in mm
  • drr.delx and drr.dely — detector pixel spacing in mm
  • drr.height and drr.width — detector dimensions
  • drr.reverse_x_axis — coordinate handedness flag
  • xray.crop — projection crop applied during registration
  • xray.mask_frames and xray.fill_frames — pre-contrast and contrast-fill frame indices

2 Expected Input Layout

Patient data must be organized under a raw_root directory with the following layout: 

<raw_root>/<patient_id>/
  cta.nii.gz
  segmentation/
    vessel.seg.nrrd
  <artery>/
    <view>.dcm
    <view>/
      parameters.pt
    <view>_masks/
      frame_000.nii.gz
      frame_001.nii.gz
      ...
Data Organization

Each artery has its own subdirectory under the patient folder. Inside it, each view is a DICOM file plus a subdirectory with the registration parameters.

  • lica/ap.dcm + lica/ap/parameters.pt — left ICA, anteroposterior
  • lica/lat.dcm + lica/lat/parameters.pt — left ICA, lateral

Specify the artery and views on the CLI, for example --artery lica --views ap lat.

3 Segmentation Inputs

The pipeline expects two types of segmentation:

CTA Vessel Segmentation

A 3D vessel label map at segmentation/vessel.seg.nrrd in NRRD format. The pipeline extracts voxels matching --vessel-label (default 2) to build the prior mesh and point cloud. The segmentation must share the CTA coordinate space.

DSA Per-Frame Masks (Optional)

Per-frame binary vessel masks at <artery>/<view>_masks/frame_000.nii.gz, frame_001.nii.gz, and so on. These are used for background suppression and visual-hull filtering. The pipeline runs without them, but the prior filtering is better when masks are available.

4 Pipeline Overview

The clinical pipeline converts registered DSA data into the same training format used by the synthetic path:

  1. DICOM loading — read the angiography stack, registration parameters, and frame ranges.
  2. Frame selection — select a fill-frame range relative to the first contrast frame.
  3. DSA MIP computation — compute per-frame DSA, optionally mask it, and collapse the selected frames into a MIP.
  4. Prior loading — extract vessel voxels from CTA segmentation and convert them into world-space points.
  5. Visual hull filtering — remove prior points inconsistent with the 2D masks across views.
  6. Dataset export — write transforms.json, projections, priors, geometry, and optional residuals.

5 CLI Reference

uv run python -m data_generation.clinical.cli \
  --patient-id case_1 \
  --artery lica --views ap lat \
  --mip-offset-start 3 --mip-offset-end 15

Required Arguments

Flag Description
--patient-id Patient identifier under the configured clinical raw-data root.
--artery Artery name such as lica or lvert.
--views One or more view names such as ap lat.

Phase and Path Options

Flag Default Description
--mip-offset-start 3 Start offset from the first fill frame for MIP generation.
--mip-offset-end 15 End offset from the first fill frame. Use 0 for all remaining frames.
--zoom-factor 1.0 Projection zoom factor applied before export.

Input and output roots are read from project.yaml automatically.

Visual Hull and Prior Options

Flag Default Description
--vh-mask-dilate-px 0 Dilate 2D masks by N pixels before visual-hull testing.
--vessel-label 2 Label ID to extract from the CTA vessel segmentation.
--max-points 100000 Maximum number of prior points sampled from the filtered prior surface.

Residual (M2) Options

Flag Default Description
--no-export-residuals disabled Turn off residual point-cloud export.
--residual-voxel-size-mm 2.0 Voxel size used for residual backprojection.

6 Output Format

The pipeline produces a dataset directory compatible with the standard training pipeline: 

<export_root>/<patient_id>/lica/
  transforms.json
  projections/
    mask_run.nii.gz
    fill_run.nii.gz
    DSA.nii.gz
  priors/
    vessel_lica_prior.ply
  geometry/
    mesh_ref.obj
    mesh_ref_filtered.obj
  residuals/
    fdk_residual.ply
    intersected_fdk_residual.ply

The transforms.json uses pose_type: "world2cam_4x4" with per-frame camera matrices and detector geometry. See Dataset Format for the full schema.

7 Frame Selection

The --mip-offset-start and --mip-offset-end flags select which fill frames are included in the MIP, specified as offsets from the first contrast frame.

  • --mip-offset-start 3 --mip-offset-end 15 selects 12 early arterial frames.
  • --mip-offset-start 0 --mip-offset-end 0 uses all contrast frames.

Set --mip-offset-end 0 to include all remaining frames from the start offset onward.

8 Visual Hull Filtering

Visual hull filtering removes prior points that are inconsistent with the observed 2D segmentation masks. Each 3D prior point is projected into every calibrated 2D mask, and only points visible in all views pass the filter.

Use --vh-mask-dilate-px to dilate the 2D masks before projection when the masks are slightly conservative.

9 Prior Source

The prior is generated by extracting a surface from the CTA vessel segmentation, optionally filtering it with the visual hull, and sampling points from the resulting mesh. This produces the M1 initialization used by training.

10 Residual (M2) Generation

When residual export is enabled, the pipeline generates additional point clouds that capture vessel regions visible in DSA but missing from the CTA prior. These serve as M2 context points during training.

  1. Project the prior into each DSA view to mask out already explained anatomy.
  2. Subtract the explained region from the DSA MIP to obtain per-view residual maps.
  3. Backproject the residual maps into a coarse 3D volume.
  4. Threshold the volume and export fdk_residual.ply and intersected_fdk_residual.ply.

11 Training with Clinical Data

The exported dataset is consumed by the standard training pipeline. The clinical export command prints a ready-to-run training command, including the prior and residual paths when they were generated. The equivalent manual command is: 

uv run python train.py \
  -s datasets/processed/clinical/case_1/lica \
  -m results/clinical_experiment \
  --Nviews 2 --seed 42 \
  --ply_path datasets/processed/clinical/case_1/lica/priors/vessel_lica_prior.ply \
  --residuals_path datasets/processed/clinical/case_1/lica/residuals/intersected_fdk_residual.ply

As with the synthetic path, prior and residual paths can also be inferred automatically when the standard folder layout or transforms.json metadata is present.
