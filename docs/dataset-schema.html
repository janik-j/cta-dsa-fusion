Dataset Format

Every training run consumes a single dataset folder. This page describes what that folder must contain and how the metadata file is structured.

Folder Structure

Point the -s flag at a folder with this layout:

my_dataset/
  transforms.json            # camera poses, imaging geometry, metadata
  projections/
    mask_run.nii.gz          # mask-run X-ray projections (3D NIfTI stack)
    fill_run.nii.gz          # contrast-fill-run X-ray projections
  mesh_ref.obj               # optional ground-truth vessel mesh for evaluation

Only mask_run and fill_run are required. The DSA images are computed automatically from the projection pair during training. If a ground-truth mesh is provided, 3D evaluation metrics such as Chamfer Distance and Hausdorff Distance can be computed.

Metadata File

The transforms.json file describes the imaging geometry and camera poses. Here is a complete working example for a 2-view setup: 

{
  "pose_type": "angles_rad",
  "dsa_convention": "fill_minus_mask",
  "N_views": 2,

  "sid": 700.0,
  "sad": 500.0,

  "proj_resolution": [512, 512],
  "proj_phy": [256.0, 256.0],
  "proj_spacing": [0.5, 0.5],

  "volume_resolution": [256, 256, 256],
  "volume_spacing": [0.5, 0.5, 0.5],
  "volume_phy": [128.0, 128.0, 128.0],

  "frames": [
    {
      "file": "ap",
      "PrimaryAngle": 0.0,
      "SecondaryAngle": 0.0
    },
    {
      "file": "lat",
      "PrimaryAngle": 1.5707963,
      "SecondaryAngle": 0.0
    }
  ]
}

Required Fields

Imaging Geometry

  • sid — source-to-isocenter distance in mm
  • sad — source-to-axis distance in mm
  • proj_resolution — projection image size in pixels
  • proj_phy — physical projection dimensions in mm
  • proj_spacing — pixel spacing in mm
  • volume_resolution — reconstruction volume size in voxels
  • volume_spacing — voxel spacing in mm
  • volume_phy — physical volume dimensions in mm

Acquisition Settings

  • pose_type — how poses are specified: angles_rad or world2cam_4x4
  • dsa_convention — subtraction convention such as fill_minus_mask or log_fill_minus_mask
  • N_views — number of input views

Per-View Frames

The frames list must contain at least N_views entries. Each frame describes one camera pose.

Angle-Based Poses

Used for synthetic TopBrain data.

  • file — frame identifier
  • PrimaryAngle — C-arm primary rotation in radians
  • SecondaryAngle — cranio-caudal angle in radians

Matrix-Based Poses

Used for registered clinical data.

  • file — frame identifier
  • world2cam — 4×4 world-to-camera matrix
  • R + T — alternative matrix decomposition

Optional Fields

  • volume_origin — volume origin offset in mm
  • geometry — reference mesh path and coordinate-space metadata
  • priors — prior point cloud metadata

Processed Dataset Layout

Synthetic TopBrain

The synthetic pipeline produces a case-root structure with view, prior, and residual sweeps. The training folder passed to -s is the view directory: 

datasets/processed/topbrain/topcow_ct_001/
  geometry/
  views/
    v2_ap_lat/            # pass this to -s for 2-view training
    v3_standard/          # pass this to -s for 3-view training
  priors/
    p_gt1p5mm/
  residuals/
    v2_ap_lat__p_gt1p5mm/

Clinical DSA

The clinical pipeline (Clinical Data) produces a single dataset folder per patient and artery configuration: 

datasets/processed/clinical/case_1/lica/
  transforms.json         # pose_type: world2cam_4x4
  projections/
    mask_run.nii.gz       # [N_views, H, W]
    fill_run.nii.gz       # [N_views, H, W]
    DSA.nii.gz            # segmentation-masked MIP
  priors/
    vessel_lica_prior.ply
  geometry/
    mesh_ref.obj
  residuals/              # optional
    fdk_residual.ply
    intersected_fdk_residual.ply

This folder is passed directly to -s for training.
